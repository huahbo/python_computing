# Project 3（进阶）：用 AI Agent 完成一次端到端数据分析

> 本题目与 Project 1 / 2 并列，属于**第二部分（第 9–12 章）**的综合作业；数据可直接沿用 Project 1 或 2。
> 与其它项目最大的区别：**除了分析本身，还要提交 AI 使用规范相关的产物**（任务卡、声明、会话记录、实验记录）。

## 一、目标

在真实数据上完成一次端到端分析，并证明：**你的结论可复现、可追溯、可解释**。

## 二、选题（任选其一）

| 题目 | 数据 | 任务重点 |
| ---- | ---- | ---- |
| A 电商用户分析 | Project 1 的数据 | 清洗 → 用户分群（聚类）→ 关键指标与图表 → 结论与建议 |
| B 交通网络分析 | Project 2 的数据 | 建图 → 中心性 / 最短路 / 社区 → 可视化 → 结论与建议 |
| C 自选（需教师同意） | 你自己的合规数据 | 自定目标与判据，须提前提交任务卡 |

## 三、交付物

1. **项目目录**：`AGENTS.md`、`src/`、`output/`、`report/`（结构见 `README.md`）；
2. **报告 PDF**（LaTeX 编译）：数据、方法、结果、局限、AI 使用声明五节齐全；
3. **任务卡**（第 10 章 02 节六件套）：目标、约束、验收标准、证据、复核、提交；
4. **会话记录**：关键任务的 `/export` 产物或截图；
5. **实验记录表**（第 11 章 06 节格式）：任务 / 模型 / 时段 / 耗时 / 花费 / 人工修改 / 结论；
6. **评审记录**：`output/review.md`，含评审意见与逐条回应。

## 四、时间安排（建议 2 周）

| 阶段 | 产出 | 参考章节 |
| ---- | ---- | ---- |
| 第 1–2 天 | 任务卡 + 计划（plan mode），确认数据合规 | 第 10 章 01–02 节 |
| 第 3–5 天 | 清洗脚本 + `verify_clean.py` + 清洗报告 | 第 11 章 02 节 |
| 第 6–9 天 | 分析与建模脚本 + 判据断言 + 图表 | 第 11 章 03–04 节 |
| 第 10–12 天 | 评审与修复（`review.md` 逐条回应） | 第 11 章 04–05 节 |
| 第 13–14 天 | 报告 LaTeX 成稿 + 声明 + 提交 | 第 0、10 章 |

## 五、评分标准

| 维度 | 权重 | 达标表现 |
| ---- | ---- | ---- |
| 分析正确性 | 30% | 判据成立：行数守恒、交叉验证区间、检验前提、异常值策略留痕 |
| 验证充分性 | 25% | 有断言、重跑一致、泄漏检查、稳健性（多种子或多窗口） |
| 使用规范性 | 20% | 任务卡完整、原始数据未改、评审闭环、权限与数据合规 |
| 报告质量 | 15% | 结构完整、图表规范、含局限与不确定性 |
| 声明与记录 | 10% | AI 使用声明逐条具体，与会话记录/实验记录一致 |

## 六、常见扣分点

- 只报最好结果，不报基线与失败尝试；
- 报告数字与 `output/` 对不上；
- 评审意见没有逐条回应（或只写"已修复"）；
- 用 Agent 直接生成结论段落，且无法解释来源；
- 未固定随机种子，导致结果无法复现。
