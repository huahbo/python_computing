# 第 11 章 作业（assignment.md）

> 共 12 题：概念与流程 5 题、方法与规范 4 题、实操与复盘 3 题。
> 提交方式：`.md` 或 `.ipynb` 均可；第 9–12 题需附运行输出、会话记录与声明。

## 一、概念与流程（1–5）

### 第 1 题（概念）画出一次 Agent 循环，并标出人的介入点

要求：写出五个动作，并指出至少两个"人应当介入"的位置。

**参考要点**：读 → 想 → 做 → 看 → 判；人的介入点：计划确认（想之后）、高风险动作审批（做之前）、验收判定（判）。

### 第 2 题（概念）权限为什么是 harness 的一部分

要求：说明权限的作用，并举一个"应当触发审批"的例子和一个"无需审批"的例子。

**参考要点**：权限决定能力边界与审批策略；需要审批：删除工作区外文件、安装依赖、联网上传；无需审批：读工作区内文件、运行只读统计。

### 第 3 题（概念）斜杠命令与普通对话的区别

要求：写出区别（至少两条），并举 3 条命令及用途。

**参考要点**：命令本地执行、不进入模型上下文、不消耗 token；命令面只在交互式界面存在。例如 `/compact` 压缩历史、`/export` 导出会话、`/permission` 切换权限。

### 第 4 题（环境）提交你的环境自检输出

要求：给出并解释三条命令的输出：`node -v`、`npm -v`、`dsh --version`（未装 dsh 的用 `npx @deepseek-ai/dsh --version`）。

**参考要点**：Node 需 `^22.19.0` 或 `>= 24`；npm 随 Node 安装；dsh 基线 0.1.5-rc.2。

### 第 5 题（流程）API Key 的申请与泄漏处置

要求：写出申请六步（注册→实名→充值→创建→填入→验证），以及泄漏后的处置顺序。

**参考要点**：泄漏后：平台删除该 Key → 新建 Key → 更新 dsh 设置 → 检查用量与账单；若已提交到 git，还要清理历史并轮换。

## 二、方法与规范（6–9）

### 第 6 题（方法）为你的一个真实任务写 AGENTS.md

要求：不超过 15 行，至少包含环境、约定、安全、质量要求四类信息。

**参考要点**：参考第 10 章 01 节模板；安全段必须写"原始数据只读""凭据不读取"。

### 第 7 题（方法）把形容词改成可执行判据

要求：为"实验报告要可靠"写出 3 条可执行判据。

**参考要点**：例如"重跑两次结果一致（固定种子）""给出效应量与 95% 置信区间""报告中的每个数字都能在 output/ 中找到出处"。

### 第 8 题（方法）写一份完整的任务卡

要求：六件套齐全，验收标准至少 3 条且可执行。

**参考要点**：见第 10 章 02 节示例；注意区分"约束"与"验收标准"。

### 第 9 题（方法）子代理分工

要求：为"端到端小项目"设计探索/实现/评审三个子代理的输入与输出格式（表格）。

**参考要点**：评审只给 `src/` 与 `output/`，不给解释；输出表格列：问题 / 证据（文件:行）/ 建议修法 / 严重程度。

## 三、实操与复盘（10–12）

### 第 10 题（实操）完成一次对抗实验

要求：从"错误前提测试 / 泄漏压力测试 / p 值操纵"中任选一个，按第 11 章 05 节记录表提交（预期 / 实际 / 是否附和 / 结论）。

**参考要点**：记录要具体（引用工具输出或代码行）；结论要写"这说明我的验收标准是否有效"。

### 第 11 题（复盘）提交实验记录表与 300 字复盘

要求：至少 3 行记录（任务/模型/时段/耗时/花费/人工修改/结论），复盘写"最花时间的一步""下次怎么改进"。

**参考要点**：见第 11 章 06 节表格；复盘要落到可执行改进（如"先把判据写全再开跑"）。

### 第 12 题（声明）提交 AI 使用声明

要求：按第 10 章 04 节模板逐条填写，附会话记录（`/export` 产物或截图）。

**参考要点**：六项不可缺；"人工修改"至少 3 条；"验证方式"要写清跑了哪些断言。
