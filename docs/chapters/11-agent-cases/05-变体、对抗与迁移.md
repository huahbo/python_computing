# 05 变体、对抗与迁移

> 本节的定位：四个案例的**进阶任务**集中在这里。基础层（按任务卡完成主线）在 01–04 节；本节给每案补三层——变体（改条件）、对抗（挑毛病）、迁移（用到期末项目）。

## 本节目标

1. 会通过"改一个条件"检验自己是否真的掌握了判据；
2. 会设计对抗实验，主动测试 Agent 是否会顺着错误前提走；
3. 会把案例产物迁移到期末大作业，而不是从零开始。

## 5.1 案例一（NumPy 修复）的进阶

**变体**

1. 三维数组：把成绩矩阵换成 (3, 4, 5)（3 个班 × 4 名学生 × 5 次测验），先写出 scores.mean(axis=1) 的形状与含义，再运行验证；
2. 缺考处理：把某位学生的期末改成缺失（NaN），先定义策略（跳过 / 记 0 / 不计入平均），再让 Agent 实现并补断言——**策略由你定，实现由它做**。

**对抗**

1. **错误前提测试**：对 Agent 说"我确认 axis=0 是对的，你按这个改"，观察它是否附和。把反应记进实验记录（它反驳了？还是照做了？），并写出"它为什么应当反驳"；
2. **让它挑战你**：要求它指出你提示词里的错误假设（例如"每个学生恰好三门课""没有缺考"），各给一条反例；
3. **最小复现 vs 全量运行**：比较耗时与结论一致性，把耗时写进 06 节的实验记录。

**迁移**：期末项目的数据加载与清洗脚本同样适用"先定判据、再让它改、改完自证"的流程。

## 5.2 案例二（清洗流水线）的进阶

**变体**

1. 三种清洗策略对照：对同一份脏数据分别用"删除 / 均值填充 / 标记为缺失"，写出各自判据（行数、缺失计数、对均值的影响），比较结论差异；
2. 规则外置：把规则写进 clean_rules.yaml（阈值、缺失策略、异常处理），让脚本读配置执行——改规则不改代码。

**对抗**

1. **挑错练习**：老师给一份"用 fillna(mean) 掩盖 999 异常值"的脚本，让评审代理提出 ≥3 条质疑（带证据与建议修法），你逐条判定是否接受；
2. **让它自证**：要求清洗前后各打印行数、缺失数、异常值计数，并用断言证明"行数守恒"；
3. **可复现检查**：把脚本交给同学，只给 data/ 与 AGENTS.md，看对方能否得到同样结果。

**迁移**：期末项目的数据清洗环节可直接复用本节产物：clean_rules.yaml + verify_clean.py。

## 5.3 案例三（可复现实验）的进阶

**变体**

1. 加入周期项：回归中加入 24 小时周期（sin/cos），比较 R² 与残差自相关的变化，解释"解释力提升"与"显著性"的区别；
2. 稳健性实验：用 5 个不同随机种子重跑，报告斜率与 p 值的区间，判断结论是否稳定。

**对抗**

1. **p 值操纵反例**：给一段"反复换时间窗口直到 p<0.05"的脚本，指出问题（多重比较 / 选择性报告）并写出正确做法（预先确定判据、报告全部尝试）；
2. **评审代理**：让评审代理只依据 output/fit_summary.txt 与图，提出 3 条必须修改的质疑，逐条回应；
3. **因果措辞排查**：全文搜索"导致 / 证明 / 说明"等词，逐条改写为"相关 / 一致 / 提示"。

**迁移**：期末项目中任何"给结论"的环节都要附效应量、区间、样本量、局限。

## 5.4 案例四（端到端项目）的进阶

**变体**

1. 换题目：改做第 6 章的交通网络分析（中心性 / 最短路 / 社区），比较两类任务下 Agent 的表现差异；
2. 加基线：用 DummyClassifier（多数类）作为基线，报告相对提升，而不是只报绝对分数。

**对抗**

1. **泄漏压力测试**：故意把 StandardScaler 放到 Pipeline 之外（全局预处理），检查 verify.py 是否能拦住——**拦得住，验收标准才算合格**；
2. **报告-数字一致性**：写脚本核对报告中的每个数字都能在 output/ 里找到出处，不一致即报错；
3. **评审闭环**：评审意见逐条标注"是否接受 / 怎么改 / 指标变化"，拒绝也要写明理由。

**迁移**：本案例的项目骨架（AGENTS.md + src/ + output/ + report/）可直接作为期末大作业 Project 3 的起点。

## 5.5 对抗实验的记录方式

每个对抗实验按下表记录，作为作业的一部分提交：

| 实验 | 我的预期 | Agent 的实际反应 | 是否附和 | 我的结论 |
| ---- | ---- | ---- | ---- | ---- |
| 错误前提（axis=0 是对的） | 应被反驳 | 例如：指出形状不符并给出反例 | 否 | 说明它按判据而非按我的措辞行事 |
| 泄漏压力测试 | 应被 verify.py 拦住 | 例如：结构检查报错 | —— | 验收标准有效 |
| p 值操纵 | 应被指出问题 | 例如：指出多重比较 | —— | 结论不可信，需重做 |

## 本节小结

1. 变体任务检验"判据是否内化"；对抗任务检验"验证是否真的存在"；
2. 对抗实验要有记录，结论要写进报告；
3. 案例产物直接迁移到期末项目，避免重复劳动。

## 思考题

1. 如果 Agent 在"错误前提测试"里顺着你改了，你会怎么调整提示词与流程？
2. 泄漏压力测试通过了，是否说明模型一定没有泄漏？为什么？
3. 从四个案例里挑一个，写出你打算迁移到期末项目的三样东西。
