## 案例背景

前面三个案例都是"修一处、做一版"；本案例是一次完整的**小项目**：给定数据集与问题，走完"探索 → 建模 → 评审 → 报告"的全流程，并且**由你担任项目负责人**——Agent 是执行团队，不是决策者。

两个可选题目（与期末大作业同源，任选其一）：

| 题目 | 数据 | 任务 | 主要章节 |
| ---- | ---- | ---- | ---- |
| A 葡萄酒分类 | sklearn 自带 `load_wine` | 分类 + 聚类对照 + 特征重要性 | 第 8 章 |
| B 交通网络分析 | 第 6 章案例数据 或 自备路网 | 中心性 / 最短路 / 社区 + 可视化 | 第 6 章 |

本案例以 A 为例，交付物包括：项目骨架、`AGENTS.md`、可复现脚本、评审记录、`report.tex`（编译成 PDF）。

## 任务卡（六件套）

| 要素 | 内容 |
| ---- | ---- |
| 目标 | 完成一个可复现的建模小项目，并输出 LaTeX 报告 |
| 约束 | 预处理必须在 Pipeline 内；报告与脚本一一对应；不得使用测试集调参 |
| 验收标准 | ① 5 折交叉验证最低分 ≥ 0.90；② 结构检查：标准化在 Pipeline 内；③ 评审代理至少提出 3 条意见且逐条回应；④ 报告含数据、方法、结果、局限、AI 使用声明 |
| 证据 | 脚本运行输出、交叉验证明细、评审意见表、编译成功的 PDF |
| 复核 | 有没有数据泄漏、指标口径是否一致、结论是否超出数据支持 |
| 提交 | 项目目录 + 报告 PDF + 会话记录 + AI 使用声明 |

## 给 Agent 的提示词（原文）

```text
【项目】用 sklearn 自带 wine 数据集做一个分类小项目，目录结构：
  agentproj/{AGENTS.md, src/, output/, report/report.tex}
【要求】
1) 先进入计划模式，给出步骤与要产出的文件，等我确认后再动手；
2) src/train.py：Pipeline（标准化 + 逻辑回归），5 折交叉验证，输出 output/cv_scores.txt；
3) src/verify.py：结构检查（标准化必须在 Pipeline 内）+ 指标断言（5 折最低分 ≥ 0.90）；
4) 用子代理做两件事：一个探索代理分析特征分布并给出 3 条建模建议；一个评审代理只看 src/ 与 output/，提出不少于 3 条质疑；
5) 把评审意见做成 output/review.md（表格：意见 / 是否接受 / 处理方式），逐条回应；
6) 最后生成 report/report.tex（中文，含数据、方法、结果、局限、AI 使用声明），并给出编译命令。
【约束】不修改 sklearn 自带数据；不把测试集用于任何拟合；所有随机过程固定种子。
```

## 子代理分工

![子代理分工](./images/subagent_split.png)

| 角色 | 输入 | 产出 | 你要做的检查 |

## 验收标准（可执行，已运行核验）

```python
import numpy as np
from sklearn.datasets import load_wine
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_wine(return_X_y=True)
pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))
scores = cross_val_score(pipe, X, y, cv=5)

assert len(pipe.steps) == 2 and pipe.steps[0][0] == "standardscaler", "标准化必须在 Pipeline 内"
assert scores.min() > 0.9, "5 折最低分不应低于 0.90"

print("5 折准确率:", np.round(scores, 4))
print("均值:", round(float(scores.mean()), 4))
print("结构检查通过：标准化在 Pipeline 内，无全局预处理泄漏")
```

```text
5 折准确率: [0.9722 0.9722 1.     0.9714 1.    ]
均值: 0.9832
结构检查通过：标准化在 Pipeline 内，无全局预处理泄漏
```

> 注意：`scores.min() > 0.9` 这样的阈值来自**你对任务的要求**，不是模型自带的结论；如果你换数据集，阈值必须重设——这正是"验收标准由人定义"。

## 人工复核点

1. **数据泄漏**：标准化、特征选择、降维是否都在 Pipeline 内（在划分之前做 = 泄漏）；
2. **指标口径**：交叉验证与测试集指标不能混用一句话描述；
3. **报告一致性**：报告里的每个数字都能在 `output/` 里找到出处；
4. **评审闭环**：评审意见不能只有"已修复"，要写清怎么改、改后指标变化；
5. **AI 使用声明**：写明哪些环节用了 Agent、你做了哪些修改（模板见 08 节）。

## 常见坑

| 坑 | 后果 | 避免方式 |
| ---- | ---- | ---- |
| 让 Agent 一把梭完成整个项目 | 过程不可解释，出错难定位 | 先计划模式，再分阶段执行 |
| 报告由 Agent 直接生成、数字对不上 | 数据与结论脱节 | 报告中的数字必须来自 `output/` |
| 评审代理与实现代理"同一视角" | 挑不出真问题 | 评审只给代码与输出，不给你的解释 |
| 忘记 LaTeX 编译验证 | 提交的 tex 编不过 | 验收标准里加"编译成功并附 PDF" |
