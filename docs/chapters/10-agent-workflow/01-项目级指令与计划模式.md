# 01 项目级指令与计划模式

> 本节解决"怎么让 Agent 一开始就按你的规矩干活"：把约定写进 AGENTS.md、复杂任务先出计划、长任务管好上下文。
> 权限与安全的完整实践见第 9 章 04 节；本节只讲"如何把权限约定固化下来"。

## 本节目标

1. 会写一份最小可用的 AGENTS.md，让 Agent 不用每次重复问规范；
2. 会用"计划先行 + 小步执行"推进复杂任务；
3. 会管理会话与上下文：一次一件事、阶段收口、换任务开新会话；
4. 会把权限与数据约定写进项目文件，而不是靠每次口头提醒。

- 第 9 章 01–04 节（概念、安装、界面与斜杠命令、权限与数据红线）。

## 1.1 项目级指令：AGENTS.md

`AGENTS.md` 是放在项目里的"常驻说明"，Agent 每次工作都会先读它。它解决的是**重复解释**问题：与其每次都说"读 CSV 要指定 UTF-8、图存到 output/、随机种子固定 42"，不如写进文件。

最小可用模板（复制到项目根目录即可）：

```text
# 项目说明
本项目是《Python 科学计算》课程的数据分析练习。

# 环境
- Python 3.12，依赖见 environment.yml（numpy / pandas / scipy / statsmodels / scikit-learn / matplotlib）
- 运行命令统一用 python <脚本名>

# 约定
- 读 CSV 一律显式指定编码 utf-8-sig，并先打印列名
- 随机过程必须固定种子：np.random.default_rng(42)
- 输出文件放 output/，不覆盖 data/ 里的原始数据
- 中文图必须设置字体：Microsoft YaHei 或 SimHei

# 安全（对应第 9 章 04 节）
- 只允许改工作区内的文件；删除、批量替换、装依赖前必须先问我
- 不读取 .credentials.yaml / .env 等凭据文件，不把它们的内容写进任何输出

# 质量要求
- 每个脚本末尾要有 assert 自检；改动后必须运行一次并贴出输出
- 不确定的地方先问我，不要擅自扩大改动范围
```

三条经验：

1. **只写"会被违反"的约定**：写得越长越没人看，Agent 也一样；
2. **写清验收方式**：能让它自查的约定，比形容词有用；
3. **把 AGENTS.md 提交到 git**：它是项目的一部分，不是个人偏好。

## 1.2 计划先行：复杂任务先要计划

任务超过"改一个文件"的量级时，先让它进入**计划模式**（界面里的 `/plan`，见第 9 章 03 节），产出：要动哪些文件、分几步、每步怎么验证、有什么风险。你确认后再动手。

| 任务规模 | 建议做法 |
| ---- | ---- |
| 一行改动、明确的小修 | 直接做，人审 diff |
| 单文件重构、补测试 | 先说明要做什么，再执行 |
| 多文件、跨目录、动数据 | **必须计划模式** + 你确认 |
| 涉及删除、覆盖、联网安装 | 计划 + 逐条确认 |

> 计划模式的价值不是"礼貌"，而是把**返工成本**从"改完发现方向错"降到"看计划发现方向错"。

## 1.3 会话与上下文管理

- **一次会话只做一件事**：上下文里塞太多目标，它就容易抓错重点；
- 长任务定期收口，让它输出"已确认的结论 / 未解决的问题 / 下一步"——这三行就是压缩后的上下文；
- 换任务就开新会话，把上一轮结论作为开场信息带过去；
- 会话过长时用 `/compact`，但**重要结论要落到文件里**（如 output/review.md）；
- 会话记录是**证据链**：提交作业时用 `/export` 导出或截图留档。

## 1.4 把权限与数据约定固化下来

审批是"事后同意"，`AGENTS.md` 是"事前约定"。两者配合：

| 场景 | 写在 AGENTS.md 里的约定 |
| ---- | ---- |
| 原始数据 | 只读，不修改、不重命名 data/ 下的文件 |
| 输出产物 | 一律写到 output/，文件名固定（便于验收） |
| 危险动作 | 删除、批量替换、安装依赖、联网前必须先说明并获得同意 |
| 凭据 | 不读取、不打印、不写入任何凭据文件 |

## 本节小结

1. AGENTS.md 把"每次都要说的规范"变成项目文件，并纳入版本管理；
2. 复杂任务先计划、后执行、小步验证；
3. 会话一次一件事，阶段收口，重要结论落盘；
4. 权限与数据约定要写进文件，而不是靠记忆。
