## 2. 原理级注意点

### 2.1 视图 vs 数据结构

G.nodes() 与 G.edges() 是视图对象，支持迭代与成员判断，但不支持“直接赋值”。要得到稳定快照用：

~~~~python
import networkx as nx
G = nx.Graph()
G.add_edges_from([(1, 2), (2, 3)])

node_list = list(G.nodes())
edge_list = list(G.edges())
degree_view = dict(G.degree())
print(node_list, edge_list, degree_view)
~~~~

### 2.2 有向图连通性的“方向坑”

有向图的 is_connected 不存在；要用 is_strongly_connected 与 is_weakly_connected。把无向图用 nx.DiGraph(G) 转换后，每条无向边会变成双向两条边，所以结论可能与你直觉不同。

### 2.3 加权 vs 无权

大多网络函数默认按“无权”处理（每条边权重=1）。一旦图带 weight 属性，要么显式传 weight="weight"，要么接受默认“无权”结果。二者结果可能完全不同。

## 3. 性能技巧

- **用生成器造图**：path_graph / cycle_graph / erdos_renyi_graph 比手动 add_node 循环快得多；
- **批量加边**：add_edges_from / add_weighted_edges_from，不要一条条 add_edge；
- **中心性按需计算**：betweenness_centrality 默认精确算法在大图很慢；可用 k 参数（k 个随机源）近似，或只计算关心的节点子集；
- **社区检测选算法**：greedy_modularity_communities 适合中等规模；超大图可用 louvain_communities（更快）；
- **复用图对象**：对同一张图反复调用算法时，先复制为 G.copy()，避免原地修改影响后续分析；
- **大图用稀疏结构**：需要把邻接矩阵交给 SciPy 时，用 nx.to_scipy_sparse_array(G) 得到稀疏矩阵，节省内存（若安装了 scipy）。

## 4. 调试建议

1. 先打印 G.number_of_nodes()、G.number_of_edges()，确认图建对了；
2. 用 sorted(G.nodes()) 检查节点是否被意外“自动补全”；
3. 报路径错误时先判断连通性：`nx.is_connected(G)`（有向用 `is_strongly_connected`）；
4. 带权问题先把边打印出来：`G.edges(data=True)`，确认 weight 属性名与数值；
5. 较慢的算法先在小图上验证（如 path_graph(10)）再加到大数据；
6. 绘图布局不稳定时，给 spring_layout 传 seed，便于复现。
