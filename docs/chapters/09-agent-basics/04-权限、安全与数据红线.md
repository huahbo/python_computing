# 04 权限、安全与数据红线

> 本节回答"能放心让它干活吗"：权限三档怎么选、审批怎么用、哪些数据不能碰、出事怎么收场。
> 基线版本：dsh 0.1.5-rc.2（2026-09-10）；权限与审批的具体界面随版本演进，以官方文档为准。

## 本节目标

1. 说清权限三档（read-only / workspace-write / danger-full-access）的差别与适用场景；
2. 掌握"从小到大放开"的实践顺序，并识别高风险动作清单；
3. 记住四条数据红线，知道课程作业与科研场景的合规要求；
4. 出事后能按固定顺序处置（止损 → 取证 → 修复 → 复盘）。

## 先修

- 01 节（失败模式与权限概念）、02 节（已装好并配好 Key）。

## 4.1 权限三档：默认最小，按需放开

| 档位 | Agent 能做什么 | 什么时候用 | 风险 |
| ---- | ---- | ---- | ---- |
| read-only | 只读文件、列目录、跑只读命令 | 第一次接触陌生项目；让它解释代码 | 极低（唯一风险是信息被读进上下文） |
| workspace-write | 只能改工作区内的文件 | 日常开发、课程作业（**推荐默认**） | 中（误改工作区文件，可用 git 回滚） |
| danger-full-access | 全盘可写、命令直通 | 受控的沙箱/容器；一次性脚本环境 | 高（可能改动系统文件、装软件、联网） |

经验规则：**能用 read-only 完成的，不要开到 write；能在工作区完成的，不要开 full-access。**

## 4.2 从只读到放开的四步实践

1. 进入新项目：read-only，让它"讲一遍"项目结构与你关心的文件；
2. 确认它读懂了（能引用具体文件与行）：切 workspace-write，只做单文件小改动；
3. 每完成一步看一次 `git diff`：确认改动范围与预期一致；
4. 涉及下列**高风险动作**时，逐条确认（不要批量放行）：

| 高风险动作 | 为什么要确认 |
| ---- | ---- |
| 删除 / 覆盖文件、`git reset --hard` | 不可逆，且可能破坏原始数据 |
| 批量重命名、批量替换 | 影响面大，容易波及其他章节/脚本 |
| 安装依赖、修改环境变量 | 改变本机环境，可能影响其他课程项目 |
| 联网上传、调用外部 API | 数据可能离开本机 |
| 访问工作区之外的路径 | 越过本次任务的边界 |

## 4.3 审批怎么用：把"同意"变成决策

审批弹窗出现时，不要条件反射点"允许"。三个问题快速判断：

1. 这个动作**属于当前任务**吗？（不属于就拒绝）
2. 它**可逆**吗？不可逆就要求先备份或先只读验证；
3. 我能**看懂**它在做什么吗？看不懂就先让它解释，再决定。

除此之外，把"长期约定"写进 `AGENTS.md`（第 10 章 01 节），比每次审批更省事：例如"禁止修改 data/ 下的原始数据""脚本一律输出到 output/"。

## 4.4 数据红线（四条，必须记住）

1. **个人隐私**：身份证号、手机号、成绩单、医疗记录、聊天记录——不贴进对话、不让它读取；
2. **涉密与未发表数据**：课题未发表数据、企业数据、竞赛内部数据——不交给云端模型；
3. **凭据**：API Key、密码、令牌、`.credentials.yaml`、`.env`——不写进提示词、不写进代码、不进 git；
4. **他人数据与版权**：未经许可不要上传/处理他人数据；教材与论文内容遵守许可。

> 判断口诀：**"这份数据能不能离开这台机器？"** 答案不确定时，默认不交出；需要处理时，先做脱敏（去掉标识列）或用本地模型（第 12 章 02 节）。

## 4.5 API Key 与凭据的日常习惯

- Key 只保存在 dsh 的凭据文件里（02 节 5.2），**不要**复制到笔记、聊天、notebook 或脚本里；
- 不要把 `.credentials.yaml`、`.env` 截图；提交作业前用 `git status` 检查一遍；
- 一旦怀疑泄漏：立即到平台删除该 Key → 新建 Key → 更新 dsh 设置 → 检查账单用量；
- 课堂练习建议用**单独的低额度 Key**，与个人长期使用的 Key 分开。

## 4.6 出事之后的处置顺序（止损优先）

| 步骤 | 做什么 | 要点 |
| ---- | ---- | ---- |
| 1 止损 | 停止会话（关掉实例或按中断） | 先别再让它跑命令 |
| 2 取证 | 导出会话（`/export`）、看 `git status` / `git diff` | 会话日志是唯一完整记录 |
| 3 恢复 | 用 git 回滚、从备份恢复数据 | 原始数据优先，脚本其次 |
| 4 复盘 | 写下"哪一步放行错了""下次加什么约定" | 更新 `AGENTS.md` 与检查清单 |

## 4.7 小结与练习

**小结**：权限三档按需放开；高风险动作逐条确认；四条数据红线；出事按"止损→取证→恢复→复盘"处置。
