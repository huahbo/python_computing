# 12. 工程化与持续演进

> 本页是第二部分第 12 章的章首页。前三章解决"会不会用"，本章解决"**能不能长期用下去**"。

## 本章概览

AI 工具迭代极快：本章写作基线是 dsh 0.1.5-rc.2，而官方在两周内就发布了多个新版本。真正可迁移的能力不是记住某个命令，而是**建立一套跟着版本走的工程习惯**：锁定版本、定期巡检、记录变更、控制成本、规范协作、按合规提交。

本章把教材自己的维护机制（版本单一事实源、巡检脚本、双周 CI、更新 SOP）作为教学案例讲清楚，并以一个综合项目收尾。

## 学习目标

1. 会为 AI 工具建立"版本单一事实源"并定期巡检（npm dist-tags + GitHub Releases）；
2. 会写更新 SOP：发现新版本 → 评估影响面 → 改文档 → 重跑验证 → 提交；
3. 会估算与控制 AI 使用成本（模型档位、token 估算、空闲时段、轮次限制）；
4. 会制定团队/课程的协作规范（AGENTS.md、评审、会话留档、AI 使用声明）；
5. 完成综合项目 Project 3：用 Agent 完成一次端到端数据分析并提交报告。
