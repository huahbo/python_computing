# 02 成本、协作与合规

> 本节的定位：把"个人会用"升级为"团队/课程可管理"：成本怎么控、协作怎么分工、数据怎么合规。

## 本节目标

1. 会为课程/团队设定 AI 使用预算与限额；
2. 会制定协作规范（AGENTS.md、评审、留档、提交）；
3. 会对数据分级并做脱敏决策；
4. 知道第三方插件与自动化脚本的风险边界。

## 2.1 成本治理

| 措施 | 做法 | 说明 |
| ---- | ---- | ---- |
| 预算与额度 | 每个 Key 设低额度；练习与个人长期使用分开 | 平台可按 Key 查看用量 |
| 模型档位 | 默认 deepseek-flash；仅复杂推理用 pro | 价格差 3–4 倍 |
| 时段调度 | 批量任务放空闲时段 | 空闲为高峰半价 |
| 轮次控制 | 一次把判据说清；长任务定期收口 | 返工是最贵的开销 |
| 用量记账 | 每次任务记录耗时与花费（见第 11 章 06 节） | 便于复盘与申报 |

## 2.2 协作规范（写进仓库）

1. AGENTS.md 进版本库：项目约定、安全约定、验收要求；
2. 任务卡进 Issue/文档：目标、判据、证据要求、提交形态；
3. 评审独立：实现与评审分离（人或评审代理），评审意见逐条回应；
4. 会话留档：关键任务导出会话（/export），与代码一起归档；
5. 小步提交：一次提交只做一件事，提交信息写清"AI 参与程度"。

## 2.3 数据分级与合规

| 级别 | 例子 | 处置 |
| ---- | ---- | ---- |
| 可公开 | 课程示例数据、公开数据集 | 可直接交给云端模型 |
| 内部 | 课题组内部整理的中间数据 | 脱敏后可用；必要时用本地模型 |
| 敏感 | 个人信息、医疗、涉密、未发表成果 | **不上传**；本地处理或改为合成数据 |

脱敏三步：去标识（姓名/学号/身份证）→ 粗粒度化（精确日期改月份）→ 抽样检查（确认无法反推个人）。

## 2.4 第三方插件与自动化风险

- 插件来自社区：安装前看维护活跃度、权限要求与代码来源；
- 自动化脚本（定时任务、webhook）：确认它会把什么数据发到哪里；
- 依赖升级：先在小范围验证，再全量使用（与第 01 节版本管理呼应）。

## 2.5 与学术诚信的衔接

第 10 章 04 节给了 AI 使用声明模板；团队/课程层面再补三条：

1. 提交物必须包含"可复现证据"（脚本 + 输出 + 会话记录）；
2. 结论部分必须由人撰写并署名；
3. 违规处理公开透明（例如：未声明使用 AI 视为学术不端）。

## 本节小结

1. 成本治理的五条：额度、档位、时段、轮次、记账；
2. 协作规范的五条：AGENTS.md、任务卡、独立评审、留档、小步提交；
3. 数据分三级，敏感数据不上传；脱敏三步走；
4. 插件与自动化要评估来源与数据流向。

## 思考题

1. 为什么"给每个 Key 设额度"比"月底看账单"更有效？
2. 团队里如何让"评审独立"真正落地，而不是走形式？
3. 你手上哪份数据属于"内部"级别？写出它的脱敏方案。
