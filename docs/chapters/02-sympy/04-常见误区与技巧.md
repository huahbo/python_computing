# 04 常见误区与技巧

> 本章为新增“查漏补缺”页：把学生最容易踩的坑集中列出，并给出正确的写法和性能技巧。

## 1. 高频误区速查表

| # | 误区 / 错误写法 | 正确做法 | 原因 |
| ---- | ---- | ---- | ---- |
| 1 | `pi = 3.14159` 然后参与符号运算 | 用 `sp.pi`（符号 π） | 浮点近似破坏精确性 |
| 2 | `x + y == y + x` 判断表达式相等 | `sp.simplify((x+y) - (y+x)) == 0` 或 `(x+y).equals(y+x)` | `==` 比较的是结构不是数学等价 |
| 3 | `sp.sqrt(x**2)` 期望得到 `x` | `x = sp.Symbol('x', positive=True)` | 若无假设，`sqrt(x**2)=|x|` 更严谨 |
| 4 | 用 `math.sin(x)` 而 `x` 是符号 | 用 `sp.sin(x)` | `math` 只能处理浮点数 |
| 5 | 以为 `lambdify` 返回符号表达式 | 它是数值函数，输入输出都是数值/数组 | 符号→数值的桥梁，不可再 `diff` |
| 6 | `A * B` 想要 NumPy 式的逐元素乘 | SymPy `Matrix` 的 `*` 是矩阵乘；逐元素需 `sp.Matrix(A.applyfunc)` | 两种库的语义不同 |
| 7 | `sp.solve(eq, x)` 忘记 `Eq` | 可以写 `sp.solve(eq, x)`（eq 视为=0）或 `sp.solve(sp.Eq(f, 0), x)` | 传入非 Eq 表达式默认等于 0 |
| 8 | 用 `dsolve(eq)` 但没定义 `Function` | `y = sp.Function('y')(x)`；初值用 `ics={y.subs(x,0): 1}` | 未定义函数会让 dsolve 报错/无法识别 |
| 9 | 期望 `simplify` 万能 | 配合 `trigsimp`、`together`、`cancel`、`radsimp` | 化简是启发式的 |
| 10 | 用 `solve` 求所有复数根当实数用 | 用 `solveset(..., domain=sp.S.Reals)` 或 `real_roots` | 不同求解函数返回集不同 |

## 2. 原理级难点：符号 vs 数值

```python
import sympy as sp
x = sp.Symbol('x')
expr = x**2 + 1          # 符号表达式
print(type(expr))        # <class 'sympy.core.add.Add'>

val = expr.subs(x, 2)    # 仍是符号（整数 5）
print(val, type(val))

num = sp.N(expr.subs(x, 2))   # 数值
print(num, type(num))

f = sp.lambdify(x, expr, 'numpy')
print(f(2))              # 数值 5
```

要点：**符号对象**不参与浮点运算，只有 `subs`+`N`/`evalf` 或 `lambdify` 才会产生数值结果。

## 3. 求解函数的选型

| 场景 | 推荐函数 | 说明 |
| ---- | ---- | ---- |
| 一元方程 | `solve` / `solveset` | `solveset` 更严谨 |
| 线性方程组 | `linsolve` | 可传方程列表或 `(A, b)` |
| 非线性方程组 | `nonlinsolve` / `solve` | 结果可能含复数解 |
| 初等矩阵运算 | `Matrix` + 方法 | `det`、`inv`、`eigenvals` |
| 符号→数值 | `lambdify` | 指定 `'numpy'` |

## 4. 性能技巧

- **优先 `lambdify` 而不是逐点 `subs`/`evalf`**：对大量数值点，先转成 NumPy 函数再向量化计算，速度可提升百倍：
  ```python
  import sympy as sp, numpy as np
  x = sp.symbols('x')
  f = sp.lambdify(x, sp.sin(x)/x, 'numpy')
  xs = np.linspace(0.001, 10, 100000)
  ys = f(xs)          # 一次向量化，比循环快得多
  ```
- **`simplify` 要慎用**：可能很慢、甚至把结果变得更长；先试 `cancel`/`together`/`trigsimp`；
- **避免反复重建符号**：把符号与常用表达式定义一次，不要在循环里重复 `symbols`；
- **大矩阵用 `sp.Matrix` 的数值化**：若最终只需数值，考虑 `sp.Matrix(...).evalf()` 或转成 NumPy `np.array(...)` 再算；
- **`nsimplify` 做“反向”精确化**：把浮点近似还原为有理数/根式（如 `sp.nsimplify(0.333333)` → `1/3`）。

## 5. 调试建议

1. 打印 `type(expr)`：确认是符号还是数值；
2. 用 `sp.srepr(expr)` 查看底层树状结构，定位“为什么没化简”；
3. `expr.free_symbols` 查看表达式含哪些符号；
4. `sp.solve` 无解时先试 `solveset`，再看 `domain`；
5. 符号求导/积分结果可疑时，用数值验证：`sp.N(expr.subs(x, a))` 与手工/数值结果对比；
6. 复杂方程先 `sp.simplify` 或 `sp.expand` 再求。
